# Fast text override benchmark — 2026-08-20

The new `extract_text_fast` path was compared with the existing structured
pipeline on the 21-PDF `benchmarks/corpus` corpus.

- Commit under test: `d813896` (working tree dirty from pre-existing changes plus this work)
- Host: arm64, 8 logical cores
- Command: `cargo run --release --example fast_text_benchmark -- --corpus-dir benchmarks/corpus --runs 2 --max-tokens 350 --output benchmarks/runs/fast-text-2026-08-20.json`
- One warmup run was discarded; one measured run was retained.
- All 21 documents succeeded in every variant; no errors.

| variant | total wall ms | median document ms | chars | chunks |
|---|---:|---:|---:|---:|
| layout, `all_texts=false` | 45,658.1 | 1,401.8 | 3,271,388 | 3,371 |
| layout, `all_texts=true` | 57,177.3 | 1,479.2 | 3,271,444 | 3,372 |
| existing structured no-layout | 20,480.1 | 609.9 | 3,270,367 | 3,824 |
| **fast text override** | **12,463.6** | **343.3** | **3,277,711** | **3,569** |

Observed on this run: fast text was 72.7% faster than layout with
`all_texts=false`, 78.2% faster than `all_texts=true`, and 39.1% faster than
the existing structured no-layout path. Enabling `all_texts` cost 25.2% over
layout with it disabled. Character totals were within 0.23% of the structured
variants, but the fast path intentionally omits locations, headings, tables,
header/footer filtering, and layout correction; the totals are not a quality
equivalence claim.

The benchmark is a directional baseline, not a release gate: repeat it on the
deployment host with at least three measured runs and representative scanned,
multi-column, Form XObject, and malformed PDFs before changing the default.
