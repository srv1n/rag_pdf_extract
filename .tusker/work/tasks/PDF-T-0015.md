# PDF-T-0015 · Bounded auditable container repairs for malformed PDFs

## Intent

- What this is: a small set of deterministic, recorded repairs for slightly-broken PDF containers — files that fail to open for trivial reasons like junk bytes before the header or a truncated end-of-file marker.
- Why it matters: real-world PDFs (email gateways, bad exporters) frequently break in these shallow ways; recovering them turns hard failures into successful extractions. Every repair is logged so output provenance is honest about the input having been touched.
- What "done" looks like: previously-failing fixtures with these defects now extract, and the result records exactly which repair was applied.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Leading BOM/whitespace/garbage before `%PDF-` is stripped and the file parses. | Automated test |
| A2 | A truncated `%%EOF` marker is repaired and the file parses. | Automated test |
| A3 | Every applied repair is reported in the extraction result (repair kind list), and unrepaired clean files report none. | Automated test |
| A4 | Repairs are bounded: a file failing after all applicable repairs returns the original typed error, not a loop or partial mutation of caller-owned bytes. | Automated test |

## Non-goals

- No xref rebuilding or general structural recovery (pdf-inspector doesn't do it either; an independent-engine fallback is a separate decision).
- No repair of encrypted or bomb-class inputs.

## Implementation notes

- Pre-parse byte-level pass in front of the lopdf load in `src/lib.rs`; operate on an owned copy, never mutate caller input.
- Repair set (reference: pdf-inspector `src/lib.rs` validation/repair helpers, MIT): header-prefix strip, `%%EO`/`%%EOF` truncation fix, bare structure-name normalization. Keep the set closed and enumerated.
- Report via the extraction result struct; coordinate the repair-attempted flag with PDF-T-0014's error type for the failure path.
- Fixtures: corrupt existing small fixtures programmatically in tests.
