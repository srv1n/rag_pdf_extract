# PDF-T-0016 · Encrypted PDF handling: password support with redaction and distinct outcomes

## Intent

- What this is: first-class handling of password-protected PDFs — accept an optional password, automatically handle the common "owner-locked but readable" case, and report exactly why an encrypted file could not be opened, without ever leaking the password into logs or errors.
- Why it matters: encrypted documents currently fail opaquely. Distinguishing "needs a password" from "wrong password" from "unsupported encryption" lets callers prompt users or route correctly, and password redaction is a hard security requirement.
- What "done" looks like: owner-only-protected PDFs extract with no password supplied; user-password PDFs extract when the right password is given; each failure mode returns its own distinct outcome; no password text appears in any log, error, or debug output.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Extraction options accept an optional password. | Automated test |
| A2 | Owner-only-protected PDFs (empty user password) extract without a password. | Automated test |
| A3 | Distinct outcomes for: password required (none given), wrong password, unsupported security handler, corrupt encryption dictionary. | Automated test |
| A4 | The password never appears in Debug/Display output of options, errors, or logs. | Automated test |

## Non-goals

- No new decryption code: encryption schemes the parser library cannot decrypt get the distinct unsupported outcome, nothing more.
- No key/certificate-based encryption.

## Implementation notes

- Check what lopdf 0.42 exposes for decryption first (do after PDF-T-0008); wire through the extraction options in `src/lib.rs`.
- Wrap the password in a newtype with a manual `Debug` impl printing `[redacted]`; reference: pdf-inspector's redacted `PdfOptions` Debug.
- Outcomes slot into PDF-T-0014's `Encrypted` variant as a sub-enum.
- Fixtures: generate encrypted PDFs with `qpdf` in a test-setup script (owner-only and user-password variants) rather than committing binaries; skip tests gracefully if qpdf is absent locally but require them in CI.
