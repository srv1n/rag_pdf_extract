# PDF-T-0012 · Byte-level page-count fallback for unparseable PDFs

## Intent

- What this is: when a PDF is so broken the parser cannot open it at all, still report an estimated page count by scanning the raw bytes.
- Why it matters: continues the "empty extractions must be attributable" work — a failure that says "unparseable, approximately 12 pages" is actionable; a bare error is not.
- What "done" looks like: parse failures carry an estimated page count wherever the parser could not produce a real one.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A byte-scan estimator counts `/Type /Page` occurrences (tolerating whitespace variants, excluding `/Pages`) without a parsed document. | Automated test |
| A2 | Total parse failures surface the estimate alongside the error. | Automated test |
| A3 | Estimator is bounded (single pass, no allocation proportional to file size beyond the read buffer). | Inline verification |

## Non-goals

- No accuracy guarantee for object-stream-compressed PDFs (estimate may undercount; that is acceptable and documented).
- No repair attempts here (PDF-T-0015 owns repairs).

## Implementation notes

- Small free function near the page-count exposure added in commit 34ce18b; wire into the error path of the main entry points in `src/lib.rs`.
- Regex-free byte scan; watch for `/Type/Page` (no space), `/Type /Page`, and reject the `/Pages` node match. pdf-inspector's `estimate_page_count_from_bytes` is the reference.
- Truncated-file fixture: take an existing small fixture and cut it mid-xref in the test.
