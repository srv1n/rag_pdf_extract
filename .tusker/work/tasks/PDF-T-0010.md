# PDF-T-0010 · Library-level parse budgets: page, object, recursion, decompression limits

## Intent

- What this is: hard limits inside the library so a hostile or pathological PDF cannot consume unbounded memory, CPU, or output before a caller-side timeout fires.
- Why it matters: today the only containment is the consumer's subprocess timeout. Decompression bombs, huge object counts, and enormous page counts run unchecked until then. The library should refuse early with a typed error instead of grinding.
- What "done" looks like: callers can set budgets (pages, objects, recursion depth, decompressed bytes, output bytes); exceeding any budget returns a clear error naming the limit hit, quickly.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Extraction options accept budgets for max pages, max objects, max recursion depth, max decompressed stream bytes, and max output bytes, with sane defaults. | Automated test |
| A2 | A decompression-bomb fixture is rejected with a limit error before exhausting memory. | Automated test |
| A3 | An over-page-budget document fails fast (before full extraction) with the limit named in the error. | Automated test |
| A4 | Default limits do not reject any document in the existing test corpus. | Automated test |

## Non-goals

- No OS-level sandboxing, CPU/RSS enforcement, or subprocess management — that stays with the consumer (rzn backend worker).
- No cancellation tokens (separate work if ever needed).

## Implementation notes

- Thread a `Limits` struct through the extraction entry points in `src/lib.rs`; enforce at the choke points: page-tree walk, object resolution, stream decompression (`miniz_oxide` inflate loop), and text accumulation.
- Decompression budget is the important one — check cumulative inflated bytes per stream and per document.
- Recursion-depth guard complements (not replaces) the lopdf 0.42 fix from PDF-T-0008.
- Error type: coordinate with PDF-T-0014 (typed taxonomy); if 0014 lands first use its `ResourceLimit` variant, otherwise add a minimal typed variant here.
- Generate bomb fixtures programmatically in tests; do not commit large binaries.
