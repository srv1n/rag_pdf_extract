# PDF-T-0008 · Upgrade lopdf to >=0.42 and add RUSTSEC-2026-0187 deep-nesting fixture

## Intent

- What this is: upgrade our PDF parsing dependency past a known denial-of-service vulnerability and prove we are protected with a test.
- Why it matters: a small crafted PDF (~21KB of deeply nested arrays/dictionaries) crashes the current parser with an abort that cannot be caught, taking down whatever process is parsing. This is the highest-priority robustness item.
- What "done" looks like: the vulnerable version is gone from the lockfile, the malicious fixture is in the test suite, and parsing it returns an error instead of crashing.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | lopdf resolves to >=0.42 in Cargo.lock; no 0.38 remains. | Inline verification |
| A2 | A deep-nesting adversarial fixture (RUSTSEC-2026-0187 shape) parses to a clean error, no SIGABRT. | Automated test |
| A3 | Existing extraction test suite still passes after the upgrade. | Automated test |

## Non-goals

- No other dependency upgrades beyond what lopdf >=0.42 forces.
- No behavior changes to extraction output beyond what the upgrade requires.

## Implementation notes

- `Cargo.toml:26` pins `lopdf = {version = "0.38", default-features = false}`. lopdf 0.39–0.42 changed APIs; expect compile fixes across `src/lib.rs` and anywhere `lopdf::Document`/object types are used. pdf-inspector's upgrade commit `1c32e4bd691bde83778ffef235019c8feac0c0c5` (firecrawl/pdf-inspector) is a reference for the same migration.
- Generate the fixture programmatically in the test (nested `[[[[...]]]]` arrays in an object) rather than committing an opaque malicious binary.
- Advisory: RUSTSEC-2026-0187 — stack overflow SIGABRT on deeply nested arrays/dicts, fixed in 0.42.0; not catchable with `catch_unwind`.
