# PDF-T-0007 · Extraction optimization pass — profile-driven wins on the corpus benchmark, quality unchanged

## Intent

With the benchmark (PDF-T-0005) and constrained-core numbers (PDF-T-0006) in hand,
make extraction measurably faster on the constrained profile — the one production
runs on — without changing what gets extracted.

Method, not guesswork: profile the benchmark run (per-phase timing inside a
document: object parsing, text assembly, layout/bbox work, output serialization;
use a profiler or instrumented timings), identify the top hot spots, implement the
highest-leverage fixes, re-run the benchmark. Candidate classes (validate against
the profile before touching): per-page allocation churn, redundant re-parsing of
shared objects, single-threaded page loops that can parallelize within a document,
serialization overhead.

**Quality is the hard constraint**: extracted output must be unchanged (byte-stable
where the repo has goldens; otherwise normalized-similarity-identical per the
backend's cross-validation approach — whitespace-normalized token equality). An
optimization that changes extraction output is a defect, not a win.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A written profile (in the task or benchmarks/ report) names the measured hot spots with their share of wall time, before any change. | Inline verification |
| A2 | Implemented optimizations produce a measured improvement on the 2-core benchmark profile — target ≥1.5× throughput (ms/page) on the corpus aggregate; record the honest number achieved, whatever it is. | focused_test |
| A3 | Extraction output is unchanged on all benchmark docs (goldens/similarity check green); full test suite green. | broad_test |
| A4 | The baseline report gains a dated "after" table so the win is auditable. | Inline verification |

## Non-goals

- No output-format changes, no new extraction features.
- No unsafe/architectural rewrites for marginal gains; if the profile says the
  parser is already I/O- or inherently-bound, reporting that honestly (with the
  numbers) satisfies this task with A2 waived — record the finding.
