# PDF-T-0009 · Fast pre-classifier: sampled operator scan with per-page OCR reason codes

## Intent

- What this is: a fast pre-scan that classifies a PDF (text-based, scanned, image-only, or mixed) before full extraction, and tags each page that needs OCR with a machine-readable reason.
- Why it matters: today we only discover a PDF was scanned or garbled after running full extraction and inspecting output quality. Empty extractions come back unexplained, and OCR routing happens late. An upfront verdict makes every empty result attributable and routes OCR per page instead of per document.
- What "done" looks like: calling the classifier on any PDF returns a document type, confidence, and a per-page list of OCR reasons in tens of milliseconds, and the same verdict is what extraction consults — never a second, contradictory computation.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A public API classifies a PDF as TextBased/Scanned/ImageBased/Mixed with confidence, sampling pages rather than fully parsing. | Automated test |
| A2 | Each sampled page needing OCR carries a reason code: `scanned`, `no_text`, `vector_text`, or `suspected_garbled_text`. | Automated test |
| A3 | Vector-outlined-text PDFs (text converted to paths) are flagged instead of silently yielding empty text. | Automated test |
| A4 | Extraction/OCR routing consumes this single per-page assessment; no separate code path can produce a contradictory OCR verdict for the same page. | Inline verification (code review of call sites) |

## Non-goals

- No port of pdf-inspector's extractor, markdown, table, or column code.
- No OCR execution changes — only routing/attribution.

## Implementation notes

- New module (e.g. `src/classify.rs`); reuse existing lopdf document access and content-stream decoding already in `src/lib.rs` — do not add a parser.
- Operator counting per sampled page: text ops `Tj`/`TJ`/`'`/`"`, font ops `Tf`, image `Do` + XObject subtype analysis, path ops (`m l c h f S re`).
- Starting thresholds (from pdf-inspector, MIT, recalibrate against our corpus): >=3 text ops per page to count as text; >=60% text pages => TextBased; 1000+ path ops AND path:text ratio >200x => vector_text; image area >=500K px for full-page scan detection.
- Default sampling: 8 pages spread first/last/middle; support full-scan and explicit page-list modes.
- `suspected_garbled_text` can defer to PDF-T-0013 (text-quality checks); land the enum now with the detector-side reasons.
- Pick ONE page-index convention (0-based) everywhere — pdf-inspector's mixed indexing is a known trap.
