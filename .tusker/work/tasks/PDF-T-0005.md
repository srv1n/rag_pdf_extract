# PDF-T-0005 · SC-judgment corpus benchmark harness — release-mode per-doc timing with normalized metrics (Mac baseline)

## Intent

The RZN backend's first live ingestion (2026-07-21) processed 21 Supreme Court
judgment PDFs in 405s wall on a 2-vCPU cloud box — a number that mixes parser work
with job-runner overhead, R2 round trips, and archive writes. To optimize anything
we first need the **parser's own numbers in isolation**, on known hardware.

Build a repeatable corpus benchmark in this repo: fetch the same 21 PDFs, cache them
locally (they are the standing benchmark corpus from here on), run **release-mode**
extraction over the set, and record per-document timing with normalized metrics.
Raw seconds-per-PDF is a misleading unit (docs range 37 KB–7.3 MB); every row must
carry size dimensions so throughput is comparable across documents and machines.

## Corpus

Same source as PDF-T-0003/0004: R2 `rzn-documents-prod`, prefix
`tenants/public/sources/70c9e920-4919-4904-b45f-37dd9b92487d/raw/` (21 PDFs,
~19 MB). Credentials: backend repo `.secrets/e2e/local.env`, `SOURCE_OBJECT_*` key
names — never print or commit values. Cache under a gitignored `benchmarks/corpus/`
dir (do NOT commit the PDFs; commit the fetch script + manifest with sha256s).

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | A `make bench-corpus` (or equivalent single command) fetches-if-missing the corpus, runs release-mode extraction over all 21, and emits a per-document table: filename, bytes, pages, extracted chars, wall ms, ms/page, MB/s, chars/s. | Inline verification |
| A2 | A committed baseline report (markdown, dated, with host/CPU noted) records the full-core Mac numbers for all 21 docs plus aggregate (total wall, median ms/page). | Inline verification |
| A3 | The harness separates fetch time from parse time (fetch is untimed or reported separately) — the parse column measures extraction only. | focused_test |
| A4 | Re-running the benchmark on an unchanged tree reproduces parse timings within normal variance (documented, e.g. ±10%), proving the harness is stable enough to detect real regressions/improvements. | Inline verification |

## Non-goals

- No optimization in this task (that is PDF-T-0007, informed by these numbers).
- No OCR-path benchmarking; text extraction only.
- The 2 known-failing bbox docs (PDF-T-0003) and 1 slice-failure doc (PDF-T-0004)
  may fail here too — record them as FAIL rows, do not block the harness on them.
